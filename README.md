# AI 电台 · 直播时的 AI 主持人

> **v0.8** · 零第三方依赖 · 纯本地语音 · Windows

一个陪你在直播间说话的 AI 电台主持。你在电脑前打游戏，它在旁边：

- **有人 @ 它就回答** —— 像电台主持人接听听众来电，带称呼、带粉丝牌、带上下文
- **没人理它就一直念稿** —— 按你写的稿子念，标点决定语气
- **一颗醒目留言 / 一个礼物都不会漏** —— 付费消息永远优先回应
- **声音可以挑，也可以是你自己的** —— 13 个角色音色 × 804 个编号，或者录一段 5~8 秒的干声克隆

语音是**完全本地的**（sherpa-onnx）：不需要显卡、不需要 PyTorch、
不需要任何语音 API，断网也能用，你说的话不会上传到任何地方。

## 安装

### 怎么装不会弹「未知发布者」

| 方式 | 会不会弹提示 | 说明 |
|---|---|---|
| **`git clone`** | **不会** | 最干净。git 下载的文件不带联网标记 |
| **ZIP 先解除锁定再解压** | **不会** | 右键 ZIP → 属性 → 勾「解除锁定」→ 确定 → 再解压 |
| ZIP 直接解压 | 第一次弹一次 | 点「运行」即可，程序会自动清掉标记，之后不再出现 |

推荐第一种：

```bash
git clone https://github.com/你的用户名/ai-radio.git
cd ai-radio
python app.py
```

不想装 git 就用第二种 —— **下载 ZIP 之后先别解压**：

1. 右键那个 `.zip` → **属性**
2. 在「常规」页最下面勾选 **「解除锁定」** → 确定
3. 现在再解压，解压出来的文件就不带标记了

### 那个提示到底是什么

```
打开文件 - 安全警告
无法验证发布者。你确定要运行此软件吗？
此文件没有包含有效的数字签名以验证其发布者。
```

**这不是病毒警告。** 浏览器下载的文件，Windows 会给它加一条名为
`Zone.Identifier` 的备用数据流（俗称 Mark-of-the-Web）。
带着这个标记的 `.bat` / `.exe` 被双击时，Windows 就会说
「无法验证发布者」—— 意思只是「这文件从网上下来的，而且没买数字签名证书」。

要彻底消除它，得买代码签名证书（一年几百到几千元），个人项目一般不买。

**程序做了两件事，让这个提示最多只出现一次**：

1. 启动时自动清除本项目内所有 `.bat` / `.exe` / `.dll` 的联网标记
2. 从 GitHub 下载 sherpa-onnx 的 exe 和 dll 之后，立刻清除标记

所以即使你直接解压，也只是**第一次**双击 `启动.bat` 时弹一下，
点「运行」之后就不会再出现了。

|---|---|---|---|
| **要做什么** | 挑一个模型和编号 | 挑一个编号 | 录一段 5~8 秒干声 |
| **有多少声音** | **13 个模型 × 804 个编号** | 103 个 | 你有几段样本就有几个 |
| **下载量** | 115 MB / 模型 | 140 MB | 176 MB |
| **速度** | **RTF 0.25**（最快） | RTF 2.0 | RTF 2.1 |

### 怎么按关键词找音色

内置音色页有个输入框，直接用中文描述：

```
低沉磁性的中年男声        温柔的女声        清亮年轻的男声        沉稳的深夜主播
```

点「🔍 帮我找」，程序会去音色表里找最接近的几个，**每个都能单独试听**，
满意就点「用这个」。

背后的原理是**实测**，不是猜的：程序给每个音色合成一句 Probe 文本，
然后量它的**基频**（越低越低沉）和**频谱重心**（越低越浑厚），
再按你的描述算出目标值排序。所以描述得越具体，找得越准。

> 第一次用之前需要跑一次测量（约 15 分钟，一次性）：
> ```bash
> python tools/profile_kokoro_voices.py
> ```
> 不跑也能用，只是「帮我找」会退化成只按性别筛。

## 怎么做一个好的克隆音色

克隆的原理是「**一段声音 + 这段声音对应的文字**」。所以这两样都很关键。

### 录音要点

| 要点 | 为什么 |
|---|---|
| **4~6 秒** | 每多 1 秒，**每次合成都多花约 0.7 秒**。超过 8 秒会明显变慢，收益却很小 |
| **只有你一个人说话** | 有背景音乐、别人插话，克隆出来会带着杂音 |
| **安静环境** | 风扇声、键盘声都会被学进去 |
| **正常语速、别念稿腔** | 它学的是你的音色和节奏，念得越自然，出来越自然 |
| **说完停 1 秒再点停止** | 不然最后一个字会被切掉 |

### 文本必须一字不差

文本框里要填**音频里实际说的内容**。差几个字影响不大，但整句不对会让音质明显变差。

比如你念的是「晚上好，欢迎收听今晚的节目」，就填这句，别写成「大家好我来直播了」。

### 想要多个声音？

多建几个音色就行：

- **人设**里可以指定用哪个音色（`voice:` 字段留空 = 跟随当前选中的）
- **音色**页可以随时试听和切换

比如「小夜」用你自己录的温柔版，「阿凯」用你捏着嗓子录的激动版。

## 关于速度（重要）

ZipVoice 是神经网络克隆，在 CPU 上跑。**实测数据**（GTX 1650 那台机器，8 线程，全精度模型）：

### 每次合成的固定开销

ZipVoice 每合成一次，都要重新处理一遍参考音频。这段开销**和样本长度成正比**：

```
固定开销 ≈ 0.67 秒 × 样本秒数
```

| 样本长度 | 每次合成先花掉 |
|---|---|
| 3 秒 | ~2.0 秒 |
| 5 秒 | ~3.4 秒 |
| 8 秒 | ~5.4 秒 |

**所以样本别录太长，4~6 秒最好。** 这也是为什么界面上会提示「偏长」。

### 步数的影响

| `num_steps` | 速度 | 噪声（频谱平坦度，越低越干净） |
|---|---|---|
| 4 | 最快（约实时） | 0.0155 ← 明显有沙沙声 |
| **8（默认）** | 慢一倍 | **0.0089 ← 最干净** |
| 16 | 更慢 | 0.0092（没有更好） |

我一开始为了速度把默认设成 4，结果噪声放大了 1.75 倍。**现在默认 8。**

### 模型精度

| 版本 | 解码器大小 | 停顿段的噪声 |
|---|---|---|
| **fp32（默认）** | 455 MB | **0.0070 ← 干净** |
| int8 量化 | 119 MB | 0.0125（有电流声感） |

两者**加载速度一样（都是 3 秒）、合成速度几乎一样**，所以除非内存紧张，就用全精度。
在「音色」页可以随时切换。

### 那直播时会卡顿吗？

**不会，因为改成了「整段一次合成 + 边生成边播」。**

之前的做法是把回复切成小段分别合成，每段都要重新付一遍固定开销，
合成速度（RTF 2.14）比播放慢一倍，段与段之间就是空白 —— 这正是「断断续续」的来源。

现在的做法是：整段一次算完，音频一边生成一边写进声卡。
写入会被播放速度自然节流，所以**音频是连续的，中间不会断**。

代价是首次出声要等，等待时间取决于文本长度。觉得太慢可以：

```toml
[tts]
num_steps = 6      # 在速度和噪声之间折中
max_chars = 120    # 更长的回复会被切成两段（会有一处停顿）
```

### 能用显卡加速吗？

理论上可以：sherpa-onnx 有 CUDA 版本，GTX 1650 能跑。
但需要额外下载 550MB 左右的 CUDA 运行时，而且你得先装 CUDA/cuDNN。
CPU 版本已经够用，所以默认没启用。

## 关键词生成音色

在「音色」页的输入框里写一句中文描述，点「生成」：

| 你写的 | 生成什么 |
|---|---|
| 低沉磁性的中年男声，适合深夜电台 | 男声底子 + 降 5.5 半音 + 更浑厚 + 慢 16% |
| 活泼可爱的少女音 | 女声底子 + 升 6 半音 + 更明亮 + 快 14% |
| 沉稳的纪录片旁白 | 男声底子 + 降 2.5 半音 + 明显浑厚 |
| 热血游戏解说男声 | 男声底子 + 升 1 半音 + 明亮 + 快 12% |

**原理（重要，别误解）**：

sherpa-onnx 里**没有** CosyVoice 那种「用一句话凭空造出新声音」的模型。
ZipVoice 是零样本克隆，必须给一段真实录音才能学。

所以这里是：**用模型自带的干净样本当底子**，
把你的关键词翻译成变调 / 明暗 / 语速，再用 DSP 作用上去。

能实现你要的效果（比如「某人的声音但更低沉」），
但声音的底子永远来自一段真实录音 —— 不可能是凭空生成的。

## 声音有回音怎么办

参考音频里的**房间混响会被模型一起学走** —— 影视片段、手机录音尤其明显。

「编辑音色」里有「去底噪 / 去回音」滑块（0 ~ 1）。它是个噪声门：
把字与字之间的残余电平压掉，混响尾巴就没得学了。

实测（人工构造的「说话 + 混响尾巴」信号）：

```
说话段  保留 100%
停顿段  压低到 0.0%
```

底子干净的正常录音用不上；影视片段建议开到 **0.4 ~ 0.6**。

## 标点决定怎么念

同一句话，写成「好。」「好！」「好？」「好……」应该是四种完全不同的念法。
打开「标点语气」（音色页底部）之后，程序会按标点切成「语气单元」，
每句用不同的语速、音量、停顿念出来：

| 标点 | 念法 | 实际做了什么 |
|---|---|---|
| `。` | 陈述 | 正常语速，停 0.22 秒 |
| `，` | 顿一下 | 停 0.13 秒 |
| `！` | 感叹 | **快 7% · 响 2.5dB**，停 0.16 秒 |
| `？` | 疑问 | **慢 3% · 响 1dB**，停 0.28 秒 |
| `……` | 拖长 | **慢 10% · 轻 2dB**，停 0.55 秒 |
| `——` | 强调 | 慢 5% · 响 2dB，停 0.32 秒 |

嫌不够可以拖「语气强度」：`0` 全拉平（不管什么标点都一个调），
`1` 默认，`2` 夸张（感叹快 14%、省略号慢 20%）。

### 说清楚这是什么、不是什么

**是**：真实的参数变化 —— 语速、音量、停顿都真的变了，你用耳朵能听出来。

**不是**：神经网络的情感建模。数据库里没有中文情绪模型
（sherpa-onnx 的 646 个模型里只有德语有个 `emotional` 版），
`GenerationConfig` 结构体里也没有情感字段。
语调起伏（`noise_scale`）是**模型级**参数，建模型时就定死了，做不到一句一变。

要真正的情感控制得上 IndexTTS2，代价是第二个 Python + 约 8GB。

## 多音字怎么处理

角色音色模型自带 `lexicon.txt`（66395 条，其中 **45494 条是多字词组**）
和 `new_heteronym.fst` 做上下文消歧。实测 27 个刁钻多音字里 23 个直接正确：

```
行长 háng zhǎng   重要 zhòng yào    音乐 yīn yuè     长城 cháng chéng
归还 guī huán     便宜 pián yi      大夫 dài fu      提防 dī fáng
着落 zhuó luò     处理 chǔ lǐ       传记 zhuàn jì     血型 xuè xíng
```

漏网的在 `voices/pronunciation.txt` 里自己加，用**同音字替换**：

```
重建 = 虫建
```

原理是汉字 TTS 先转音素再合成，所以只要 虫 和 重(chóng) 同音，
合成出来的声音完全一样。这样不需要懂音素记号，对任何引擎都有效。
内置 95 条规则（银行、重复、音乐、长城、归还、处理、放假…）。

## 音色微调（不改样本也能换声音）

克隆出来是什么声音，**完全取决于那段参考音频**。所以想让声音更低沉，
不用重新录 —— 把参考音频降调再喂给模型就行。

「音色」页 →「编辑」→ 打开**音色微调**：

| 预设 | 效果 |
|---|---|
| 原声 | 不动 |
| 更低沉 | 降 3 个半音，稍厚 |
| 电台男声 | 降 4 个半音 |
| 沉稳旁白 | 降 2.5 个半音，明显浑厚 |
| 更年轻 / 更明亮 | 升调，提亮 |

也可以自己拖**音调**（±8 半音）和**厚度**两个滑块，右边实时显示「偏低沉 · 稍厚」这样的描述。

### 代价

降调会把波形拉长：

| 音调变化 | 样本长度变化 | 每次合成多花 |
|---|---|---|
| -3 半音 | +19% | ~0.9 秒 |
| -6 半音 | +41% | ~2.1 秒 |

升调则相反（变短、更快）。

### 不会毁掉原声

`original.wav` 存的是你导入/录制时的原声，微调只影响 `sample.wav`。
所以可以来回调，不会累积失真。老音色第一次调节时会自动补建 `original.wav`。

## 只让观众听见，自己听不见

默认情况下 AI 的声音从**系统默认输出**出来，你自己也会听到。想做到
「只有观众听得见」需要一个**虚拟声卡**，因为声音总得先送到某个设备上。

### 现在有没有装好？

「设置」页的输出设备下面会**自动检测**并告诉你能不能用：

- **✓ 检测到虚拟声卡** → 直接照它给的三步做
- **△ 没检测到** → 它会告诉你去装 VB-CABLE

### 装 VB-CABLE（免费，2 分钟）

1. 下载 <https://vb-audio.com/Cable/> （Windows 版，解压后右键 `VBCABLE_Setup_x64.exe` → 以管理员身份运行 → Install Driver）
2. **重启**（Windows 需要重启才认这个设备）
3. 回到软件「设置」页点「刷新」

### 接线

| 步骤 | 做什么 |
|---|---|
| 1 | 软件「设置」→ 输出设备 → 选 `CABLE Input` |
| 2 | OBS → 添加来源 → **音频输入采集** → 设备选 `CABLE Output` |
| 3 | 完成。AI 的声音只进 OBS，你自己的耳机里不会响 |

### 为什么不能纯软件实现

声音必须从某个设备出来。没有虚拟声卡的话，唯一的物理出口就是扬声器
或者耳机，你自然会听到。所谓「虚拟声卡」就是一条**只在系统内部存在的
音频线**，一头接软件、一头接 OBS，不经过任何真实扬声器。

如果你只有扬声器和耳机两个真实设备，可以退而求其次：让 AI 走扬声器、
自己戴耳机，然后 OBS 用「音频输出采集」抓扬声器那个设备。
缺点是扬声器会外放，麦克风可能收进去。

## 人设怎么写

人设正文会**几乎原样**交给 AI。内置三个人设可以直接参考：

| 文件 | 主持人 | 风格 |
|---|---|---|
| `深夜电台.md` | 小夜 | 温柔、慢节奏、深夜陪伴 |
| `热血解说.md` | 阿凯 | 快、激情、游戏解说 |
| `老白.md` | 老白 | 沉稳、讲故事、中年电台 |

写清楚四件事就够了：**它是谁**、**什么性格**、**怎么跟观众说话**、**绝对不能做什么**。

> 最后一条特别重要，至少要写「不要说自己是 AI」「不要念旁白」——
> 不然 TTS 会把「（笑）」这种括号动作也念出来。

## 常见问题

### 双击 启动.bat 后一堆报错

`启动.bat` 必须保持**纯英文 + CRLF 换行**。`cmd.exe` 是按控制台代码页
逐字节解析批处理的，往里写中文会让它把字符拆错，报出 `'on' is not recognized`
这类莫名其妙的错。所有中文提示都由 Python 输出。

跑 `python tools/selftest_units.py`，有一节专门检查这个。

### 引擎下载失败 / 卡住

国内直连 `github.com` 经常握手失败。程序已经内置了**多镜像回退 + 断点续传**，
会自动重试。如果实在不行，手动下载这三个：

| 文件 | 放到 |
|---|---|
| `sherpa-onnx-v1.13.8-win-x64-shared-MD-Release.tar.bz2` | 解压后把 `bin`/`lib`/`include` 放进 `sherpa/` |
| `sherpa-onnx-zipvoice-distill-int8-zh-en-emilia.tar.bz2` | 解压后整个目录放进 `models/` |
| `vocos_24khz.onnx` | 放进 `models/` |

地址都在 <https://github.com/k2-fsa/sherpa-onnx/releases>，
用 `https://ghfast.top/` 前缀加速。

### 录音按钮点了没反应 / 说没找到麦克风

检查 Windows 的麦克风权限：**设置 → 隐私和安全性 → 麦克风**，
确认「允许桌面应用访问你的麦克风」是开的。

如果还是不行，就直接用别的工具录一段 **16 位 PCM WAV**，用「选文件…」导入。

### 我的录音是 m4a / mp3，能用吗？

**不能**，必须是 WAV。原因：Python 标准库解不了 mp3/m4a，我也不想为了这个
塞一个几十兆的 ffmpeg 进来。

两个办法：

1. **用软件里的 🎙 录音**（推荐，它直接存 WAV）
2. 用 Audacity 之类的转一下，导出时选「WAV (Microsoft) 16-bit PCM」

> Windows 自带的「录音机」存的是 m4a，所以别用它。

### 克隆出来的声音不像

按重要性排序：

1. **样本里有杂音** —— 换安静环境重录，别开背景音乐
2. **文本和音频对不上** —— 文本必须是音频里实际说的内容
3. **样本太短或太长** —— 5~8 秒最佳，太短学不到特点，太长反而糊
4. **样本本身情绪和你要的不一样** —— 想要温柔就温柔地录

### 声调听着不对

这批角色音色每个模型有 **804 个说话人编号**，编号之间的质量差别很大 ——
实测同一个模型里，有的编号基频分布正常，有的编号声调明显发飘。

**换编号是最有效的办法**：选中一个模型，用「下一个 ▶」连着试听，
找到听着正常的那个（试听时留意四声是否分明，尤其上声是不是往下沉）。

读音纠正表（`voices/pronunciation.txt`）只解决「哪个字读哪个音」，
解决不了「声调发飘」—— 那是说话人本身的问题，只能换编号。

### 声音有杂音 / 电流声 / 沙沙声

按这个顺序排查：

1. **`num_steps` 是不是被调低了。** 设成 4 会让噪声放大近一倍。回到 8。
2. **模型精度是不是 int8。** 「音色」页切成「全精度」—— 量化版在句子停顿处有明显电流声。
3. **样本本身有没有底噪。** 影视片段常带背景音乐，会被一起学走。换安静环境重录。
4. **降调太多。** 有些声音降到 -6 半音以下会开始发闷、发毛。

### 念稿时有时会停顿很久

排查顺序：

1. **空闲间隔设太大了。** 「设置」页的「安静多久之后开始找话说」默认 6~12 秒，
   但**实际静默 = 这个间隔 + 大模型(~1秒) + 合成时间**。
   样本 8 秒时合成又要 5.6 秒，加起来就二十多秒。调到 6~12 秒之间。
2. **样本太长。** 每多 1 秒，每次合成都多花约 0.7 秒。
3. **大模型网络抖了。** 单次请求超时现在默认 20 秒、重试 1 次，
   最坏约 45 秒。日志里会写。

界面上会显示「正在合成语音…」的进度提示，所以正常情况下你知道它在忙，
不是卡死了。

### 念稿断断续续，不能一口气念完

老版本会把回复切段分别合成，段与段之间有空档。现在已经改成
**整段一次合成 + 边生成边播**，正常情况下不会再有这个问题。

如果还有，多半是**样本太长**：每多 1 秒，每次合成多花约 0.7 秒。
把样本换成 4~6 秒的版本。

### 说话太慢 / 有延迟

见上面「[关于速度](#关于速度重要)」。核心是三件事：
样本短一点、`num_steps=4`、`max_chars` 调小。

### AI 一直不说话

看「电台」页的日志：

- **没有 API Key** → 去「设置」填
- **日志说「连续 3 次调用模型失败，已自动暂停」** → 程序防刷屏停了，
  红字会显示原因。修好后点「▶ 继续说话」
- **收到弹幕但没回应** → 检查弹幕里有没有叫它的名字（人设里的名字和别名）

### 收不到弹幕

1. **房间号对不对**，**房间在播吗**
2. **填 Cookie**（「设置」页）—— 弹幕会更全、也不容易被风控拦
3. 用 `python run.py danmaku 你的房间号` 单独观察 30 秒

> Cookie 等于你的登录凭证，只存在本地 `config.toml`，不会上传。

### 日志在哪

`logs/radio.log`（自动轮转，最多 6MB）。

## 技术说明

### 为什么是零依赖

`requirements.txt` 里什么都没有，这是**刻意的**：

- 新版 Python 上很多带 C 扩展的包没有预编译轮子，装起来要编 C 代码
- 直播软件最怕"关键时刻少一个包"

所以下面这些全是自己用标准库实现的：

| 功能 | 通常要用的包 | 本项目 |
|---|---|---|
| 图形界面 | PyQt / 一堆封装 | 标准库 `tkinter` |
| 语音克隆 | `torch` + `indextts`（几 GB） | 自己 ctypes 调 sherpa-onnx C API |
| 麦克风录音 | `sounddevice` / `pyaudio` | 自己 ctypes 调 winmm `waveIn` |
| 音频播放 | `sounddevice` / `pygame` | 自己 ctypes 调 winmm `waveOut` |
| WebSocket | `websockets` | 自己写（RFC 6455） |
| B 站弹幕 | `blivedm` | 自己写（二进制协议、zlib、心跳、重连） |
| HTTP | `requests` | 标准库 `urllib` |
| TOML | `pyyaml` / `toml` | 标准库 `tomllib` + 自写序列化 |

### 为什么同时保留 Kokoro 和 ZipVoice

| | Kokoro | ZipVoice |
|---|---|---|
| 声音来源 | 模型自带 103 个 | 你提供的音频样本 |
| 每句话的固定开销 | **无** | 约 0.67 秒 × 样本秒数 |
| 杂音/电流声/回音 | 不会有 | 参考音频有什么就学什么 |

实测两者在这台机器上 RTF 都在 2 左右（CPU 纯算力限制），
但 Kokoro **没有固定开销**，所以长文本的效率明显更好。

### 为什么是 ZipVoice 而不是 IndexTTS2

| 方案 | 配置要求 |
|---|---|
| **IndexTTS2** | 要 `torch`（无 Python 3.15 轮子）→ 必须再装一个 Python 3.11；CUDA 版 torch 约 3GB；模型约 5GB；要求 6~8GB 显存 |
| **ZipVoice（本项目）** | 纯 ONNX，**CPU 就能跑**，总共约 250MB，不需要显卡 |

ZipVoice 是零样本克隆：给一段参考音频 + 对应文字，直接就能用那个音色合成。
音质不如 IndexTTS2，但在这台机器（GTX 1650 4GB）上**能跑起来**是第一位的。

### 三个实现上的坑（都已绕过）

1. **官方 cli 每次都重新加载模型**（约 3 秒）。
   所以改成 ctypes 直连 `sherpa-onnx-c-api.dll`，模型常驻内存。

2. **每次合成的固定开销和参考音频长度成正比**（约 `0.67 秒 × 样本秒数`）。
   所以建议样本控制在 5~8 秒，并在界面上实时提示。

3. **B 站弹幕默认用 brotli 压缩，而 brotli 没有新版 Python 的轮子**。
   程序在鉴权包里声明 `protover = 2`，让服务器改用明文/zlib 传输。

4. **音量不是调系统音量**，而是直接缩放 PCM 采样 ——
   直播时你自己听歌的音量完全不受影响。
